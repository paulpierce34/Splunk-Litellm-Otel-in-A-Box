Harness-level mitigation layer — configure the agent before it ever runs (opencode.json / hermes.json)

The gateway constrains what agents can reach; the harness config constrains what agents can do. Both layers ship with the product — no extra infrastructure:

Pitch line: "deny-by-default agents" — permissions scoped in config, commands allowlisted, destructive actions gated behind a human approval, and every approval logged to the same Splunk index. A rogue agent inherits only what its harness config grants, and can only reach models through a keyed gateway.

Why the insider beats the air gap

  • Air gap stops outsiders — insiders are already inside it
  • Rogue agents give one insider autonomous, credential-carrying reach
  • Poisoned artifacts ride the approved import path — the gap's own supply chain
  • Poisoned context needs only write access to a RAG source or MCP feed

The chokepoint thesis

  • Every LLM call — human or agent — flows through LiteLLM
  • No key, no model: rogue agents can't move without attribution
  • Rate limits + budgets cap any single insider's burn
  • Guardrails validate what goes in and what comes out

Detection Plane — insider deterrence

  • Every prompt indexed with per-key/per-user attribution (AU-12)
  • Real-time Splunk alerts: volume spikes, fan-out, budget trips, 401s
  • Prompt scan for IP markers / canary secrets leaving the enclave
  • Pipeline heartbeat — alert if telemetry suddenly stops (T0138)
